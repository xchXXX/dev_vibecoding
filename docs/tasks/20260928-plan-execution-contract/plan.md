# Plan 可读性、批准分工与结果预检

用户已批准本次方案；普通实施，不以被改造的 GTO 驱动自身。主代理完成文档、测试、代码，整体 Review 与验收分别委派独立子代理。

## 目标与范围

让读者看懂关键实现并能审查分工；把计划代理与真实绑定连接起来；保护批准的依赖；减少结果格式导致的无效返工。范围仅为 GTO 真源、示例、相关现行文档与测试。药代项目仅作展示样例。

## 实施顺序

1. 定向失败测试与行为约定。
2. planned_agent_key、批准范围、派发与派生返工任务检查。
3. 共用正式接收逻辑的只读结果预检，聚合可独立判断的格式错误。
4. 人读呈现、任务表、使用说明与三种样例。
5. 相关回归，整体 Review，修复并复审，再独立验收。

## 验证合同

- minimal_repro：最小合同中计划 A 实际 B 未被拒绝；格式错误只能正式提交后发现。
- hit_proof：直接调用真实绑定入口和结果入口，检查拒绝原因及状态/文件不变。
- diagnostic_checks：schema、批准指纹、同名/异名代理映射、模板选择与缺失字段检查。
- acceptance_checks：合法测试代理复用验收；错派拒绝；依赖未就绪拒绝；预检与接收一致；返工正常继承；生成展示与合同一致。
- non_goals：不增加代理注册表、调度框架或测试/验收全面隔离禁令；不改药代业务、不重写历史任务。
- review_evidence：定向 Red/Green、相关回归、原始工作区快照、独立审查与验收记录。

## 关键约定

计划代号相同表示复用同一真实代理，不同表示不同代理。派发前检查前置条件，绑定成功后放行施工。机器不能拦截绕过控制器的平台消息，此限制必须如实披露。

正文优先展示问题、实现因果、结果、风险与验收实例；文字解释原因、图解释关系、表便于对照。完整要求保持可核对。维护同一 state 真源，Markdown 是展示。
