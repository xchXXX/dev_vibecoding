- 先按当前操作判断缺失项所属层级，且只有任务已明确依赖该项、包名与安装范围均清楚时才自动安装；不要用 Python 临时代替 `jq`、`rg` 等已知的系统工具，也不要换平台绕过缺失项。
- 系统层工具安装到当前 WSL 发行版：`git` 使用 `git` 包，`jq` 使用 `jq` 包，`rg` 使用 `ripgrep` 包，Linux Node 使用 `nodejs` 与 `npm` 包。它们是发行版共享工具，不写入项目依赖文件，也不安装到 Windows 环境。
- 项目 Python 依赖写入项目的 `pyproject.toml`、`requirements*.txt` 或 lock 文件，并安装到该项目的 Linux `venv`；项目 Node 依赖写入 `package.json` 与 lock 文件，并安装到该项目的 Linux `node_modules`。不要把项目依赖提升为发行版包，也不要跨项目复用 Linux `venv` 或 `node_modules`。
- 浏览器要区分 Windows 人工浏览和 WSL 自动化运行时：人工在 Windows 浏览器中检查页面不要求安装 WSL 浏览器；自动化使用 Playwright/Chromium 时，将对应依赖和浏览器运行时安装在当前 WSL 项目运行时，不混用 Windows 浏览器或其缓存。
- 对当前任务确实需要、包名和来源及目标 WSL 发行版明确、且仅安装缺失包（发行版官方包）的系统层操作，即使命令需要 `sudo`，也视为可自动执行，无需再次授权。
- 新增第三方源、广泛升级、卸载、发行版变更、来源不明的软件包或仓库、安装范围不清、或超出当前任务依赖的安装，先说明原因、影响与目标范围并取得授权；未经授权不扩大安装、切换包源或升级发行版。
