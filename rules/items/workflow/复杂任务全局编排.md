- 涉及多阶段、多子任务、依赖编排或统一验收的任务，只使用 `global-task-orchestrator`（GTO）控制面；`docs/ai/tasks/<task_id>/state.json` 是唯一真源，不生成第二套状态、报告或 review package。
- 语义判断由 Codex 完成。普通委派时，Codex 读取 `task.md` 的“做什么、不做什么、会改哪里、怎么实施、怎么验收、有哪些风险”六要点，并在平台真实派遣 prompt 中显式给出 `assignment`、`read_paths`、`write_paths` 与验收要求。控制器只机械维护 `state.json`、`events.jsonl`，以及通过 `build-review-brief` 生成复审 brief。
- state 只保存短摘要、仓库相对路径、哈希、commit range、命令名与结论，不保存完整 stdout、diff、prompt 或聊天记录。正式大对象保留在其原始位置，state 只记录路径、哈希与摘要。
- 子代理无历史派发必须使用平台真实参数，派发后记录平台返回的真实 `platform_agent_id`、`brief_kind` 和 `brief_sha256`；提示词不能冒充隔离证明。
- 进入写入阶段前只读检查并记录 primary checkout 或 linked worktree、branch、`HEAD`、dirty paths 与 write overlap；未决 overlap 阻止实施。控制器不得自动创建、切换、移动、删除或清理 worktree。
- finding 采用稳定 ID，沿 lineage 返回原实现者，并由原 reviewer 对 finding、fix delta 与必要证据范围化复审；范围扩大必须升级，同一 finding 最多三轮。
- 任务完成前必须由独立 reviewer 对最新 `HEAD` 或最终变更哈希给出 `final/pass`；版本变化后旧结论失效。
