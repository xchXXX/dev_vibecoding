# 容器构建与增量交付

本文件是跨项目容器构建、缓存和增量交付的规则真源。分支、候选和授权仍按[分支与发布管理](分支与发布管理.md)执行；仓库地址、平台、凭据方式、服务器和保留数量由项目配置维护。

## 正式交付路径

- 联网容器的日常发布默认由 CI 对固定源码构建一次、测试并推送镜像仓库，服务器直接按批准 digest 拉取，复用已有层。不把 `docker save` 全量镜像归档、Actions 大文件下载或本机中转当作常规链路。
- 离线环境或已核实的仓库限制才采用例外传输，说明适用原因、范围及校验办法；不要因暂时未配置仓库直接退回全量中转。改造前核实在途构建、传输、维护和切换阶段，在安全边界接入，不取消正在切换的发布，不重复已完成步骤。
- 发布清单固定源码提交、构建 run/attempt、平台、仓库、镜像摘要及必要配置/恢复快照摘要。重试沿用同一产物；不重新构建、不重新解析浮动 tag 或 `latest`，不把缓存命中当作产物批准。
- 仓库 index、平台 manifest、config 及宿主运行 ID 的关系必须显式定义和实际核实。使用注册表实际内容的摘要；不能把本地构建 ID 直接当作注册表摘要，也不能以“任一摘要匹配”放宽身份检查。
- 必要的运维配置和恢复快照以小型不可变产物保留，凭据不入包。镜像拉取、空间检查、digest 校验和实际服务用户探针通过后，才进入维护、排空、备份、必要迁移及受影响服务替换；只准备的授权不得调用切换或提前执行新包中的特权代码。

## 两级缓存与层边界

- 固定基础环境、稳定用户及高成本依赖层在前，频繁变化的源码与配置在后；每层只接收影响它的输入。源码变化不应使基础或依赖安装层失效。
- CI runner 会重建时，使用受信作用域的 BuildKit 外部缓存；安装层确需重建时，仍复用包管理器的持久下载缓存。只换镜像仓库而每次重新下载、安装全部依赖，不算完成缓存优化。
- 缓存至少按操作系统、架构、运行时和依赖锁分区，明确读写主体。下载缓存不烘入运行镜像、不保存认证文件；锁定和校验仍执行，不能为命中缓存保留不兼容依赖。
- 失败保留已完成的层和有效缓存；有损坏证据才定向处理。不全局 prune，不清空共享缓存。镜像版本清理按项目成功版本策略执行，保护当前、运行中、回滚和明确保护的引用；多个发布共享 digest 时不能删除仍被保留版本引用的镜像。

## 权限与真实验收

- CI 推送和服务器拉取使用分离的最小权限，私有镜像不得为便利而公开。临时作业凭据不得进入命令参数、日志、构建上下文、镜像、普通证据或缓存；准确说明其权限和存活期，不把仓库作业 token 描述成只有单镜像权限。
- 沿用受限正式接收入口和精确产物批准门禁，不给上传账户增加任意 Docker/sudo 权限。错误或未批准的 digest 必须在维护前拒绝；拉取或探针失败保留旧服务访问，并保留同产物重试依据。
- 用真实构建/拉取证据分别验证：同一镜像重复拉取不重复下载层；源码变化复用基础/依赖层；依赖变化只影响相关层；失败重试保持 digest 并复用已完成层；回滚使用已验收的保留镜像。
- 记录层摘要、缓存命中、下载量及构建/拉取/维护耗时，分开冷启动与后续复用。Docker 进度层字节、描述符大小和网卡总流量各有边界，不互相冒充，也不以 Dockerfile 静态结构或一次健康检查代替性能及业务验收。
