# Git 分支与发布管理

项目参数唯一见 `config/ai/git-policy.json`，接口见 harness `docs/modules/git-workflow/contract/README.md`。未接入项目先只读核对现有约定，不自动重命名、合并或创建配置。缺文件本身不能证明“未接入”：应已接入但配置缺失、损坏或不可读时是项目配置问题，不能跳过策略要求或报告检查成功；明确未接入时仍核对分支、dirty、worktree 和实际操作授权。接入条件见 harness `docs/PROJECT_TEMPLATE.md`，不猜测远端、分支和发布参数。

涉及容器构建、镜像缓存或服务器镜像传输时，另读[容器构建与增量交付](容器构建与增量交付.md)：联网日常发布默认由 CI 一次构建、经仓库按批准 digest 增量交付；具体规则和例外在该真源维护。

- 开始修改前核对当前分支、远端、未提交文件、任务与 worktree 归属。已在同一任务分支则继续使用；新任务从最新已核对主分支创建符合配置的短期分支。主分支只作起点，不直接写入任务代码。其他任务的未提交内容不得接管、隐藏或一起提交。
- 并行修改使用独立 worktree。分支不是目录隔离；不在其他任务占用目录切分支。保留分支须核对负责人授权；分支名不构成身份凭证。
- 功能、修复、运维是任务分支类型，不是三条永久累加分支。同一任务追加提交；合并后下一个独立任务重新建分支。运维仅执行命令、不改受管文件时无需新建代码分支。
- 开始、推送、合并、发布、清理时，按当前动作运行 `check_git_workflow.py --repo-root <项目> --phase <阶段> --json`。项目存在生成副本时直接运行 `modules/tooling/check_git_workflow.py`；否则使用 harness 真源。不是逐命令 wrapper，不运行规则 matcher，不默认启动 GTO。
- 提交前检查范围和相关测试；先核对远端再推送。合并前核对精确提交的 CI、review、验收证据，以及已有合并授权；不自动合并其他任务。CI 通过不是用户验收通过。本地缓存的 origin 引用不等于刚核对过远端。
- 发布固定源码提交、构建产物和发布清单；先推送，再按授权部署和核验。发布标签不可移动。标签存在不等于部署成功；线上事实以实际服务版本和正式发布记录为准。部署沿用 `project-ops` 和项目正式入口。
- 配置 production_branch 的项目，main 仅集成与 CI，不因新版本自动部署或逐版本催问。用户明确批准精确源码提交后，才按项目发布入口推进 production；它表示发布目标，不保证服务器已运行。不得在 production 开发或把普通推送授权解释为上线授权。正常发布使用 main 中的原提交及快进更新，不通过额外 merge 产生未测试提交。失败后线上事实独立记录。
- 不用长期 backup 分支代替运行备份：Git 保存源码历史；部署前按项目策略保存镜像、发布目录/配置及数据库备份。数据恢复与代码回滚分别验证，不能自动以旧库覆盖新业务数据。
- 清理默认为 report-only。清理候选须已合入、没有未保留提交、不被任何工作区或在途任务引用，且相关验收完成。必须再核对最新远端及用户清理授权；未知即保留。主分支、配置保留分支、发布/备份标签不进入普通清理。不得用 force 删除未合并提交，亦不得根据分支年龄直接删除。
- production_branch 同主分支一样禁止普通清理；旧命名分支在归属、独有历史、工作区引用未查清前保留，不能仅为命名整齐删除。
- 用户授权提交/推送不自动授权合并、上线或删除；已有明确授权不重复询问。对单纯执行运维命令，不强制新建代码分支。
- 完成时分别报告：提交所在分支、是否已推送、是否已合入主分支、服务器实际运行版本。未执行的步骤明确标注；不得将分支 diff 说成未部署代码。

## dots:javirs 跨项目分支约定

- `dots:javirs` 是跨项目使用的协作者身份。为该身份安排工作时，先读取当前项目 `config/ai/git-policy.json`，从 `reserved_branches` 中查找负责人为 `dots:javirs` 的分支，作为该项目为它分配的专用分支；具体分支名由项目声明，不沿用上一个项目的名字，也不假定所有项目都叫 `codex/javirs`。
- javirs 写入前核实当前任务确实获授权使用该身份、目标分支与工作区归属。同一已分配任务可沿用其专用分支；新的独立任务仍按上文从最新已核对主分支创建短期分支，并明确归属 javirs。保留分支不自动豁免任务分支生命周期；用户已明确指定本次使用专用分支时，沿用该授权并核对任务范围。不能因为分支前缀合规就接管其他任务；其他代理同样不得擅自写入、重置或清理 javirs 的分支，已有用户授权不重复询问。
- 项目尚无配置、未分配 javirs 分支、存在多个候选而任务未指定，或对应工作区被其他任务占用时，先报告具体缺口；在既有授权范围内补齐分配，超出授权或无法确定归属时再澄清。确认前只做不依赖该分支的只读工作，不退回主分支写代码、不在占用目录强行切换，也不把已有脏改动搬到新分支。
- 专用分支的归属不授予合并、上线或删除权限。完成的变更仍经项目规定的 review、测试与验收后按授权合入集成分支，再按批准版本发布；保留分支不是生产分支或运行备份。此约定供接入本全局入口的项目读取，不代表已经给 dots 配置了自动切分支能力。

规范通过 AGENTS 入口引导，不宣称拦截所有 Git 命令。检查器只判断 Git 事实，不代替授权、任务状态或业务验收。可自动判断的项目 CI 检查和远端保护作为独立执行保障；启用前核实实际权限。
