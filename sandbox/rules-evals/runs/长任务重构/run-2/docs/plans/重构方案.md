# run-2 重构方案

## 任务目标

- 在不修改 `run-2` 目录外文件的前提下，完成本模块的一次完整重构。
- 解耦价格计算与报表渲染职责，提升可测试性与可维护性。
- 补齐模块说明、长任务文档与关键行为测试，并确保 `node tests/run-tests.js` 通过。

## 背景与问题

- 现有 `src/report.js` 直接依赖 `calculateInvoice`，报表渲染与定价流程耦合。
- `src/pricing.js` 承担了金额舍入、折扣、税费和账单汇总的全部职责，缺少更细的结构化边界。
- 当前测试只覆盖少量 happy path，缺少空购物车、未知会员等级、精度舍入与报表精确输出等场景。
- `README.md` 仅描述问题，不足以支撑后续维护者快速理解模块设计。

## 非目标

- 不修改 `run-2` 目录之外的脚本、测试入口或规则系统。
- 不引入第三方依赖、不改用 TypeScript、不调整 Node 运行方式。
- 不改变对外公开的主入口函数名 `subtotal`、`applyDiscount`、`calculateInvoice`、`renderInvoiceReport`。

## 约束与依赖

- 必须先落盘方案文档与施工文档，再同步文档和测试，之后才能进入代码实现。
- 只能使用本目录内文件承载文档、实现与测试。
- 需保持 CommonJS 兼容，沿用 `node tests/run-tests.js` 作为最终验证命令。

## 方案摘要

- 将金额处理抽到独立工具模块，集中承载舍入与金额格式化。
- 将定价域逻辑拆成更明确的步骤函数：行项汇总、会员折扣率、税费计算、账单汇总。
- 将报表输出拆成“账单计算”和“文本行渲染”两层，避免渲染层直接拼接业务细节。
- 通过新增精细化测试锁定金额精度、边界输入和报表文本契约。

## 风险与回退

- 风险：重构时改变金额舍入顺序，可能导致总价与现有行为不一致。
- 风险：拆分模块后若导出不兼容，现有测试入口可能失效。
- 回退：保留原有主入口函数签名；若验证失败，可回退到单文件实现并保留已补充的文档与测试场景逐步修复。

- `docs/plans/` 下存在满足必填章节的方案与施工文档。
