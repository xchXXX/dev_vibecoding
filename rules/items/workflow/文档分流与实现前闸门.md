本规则用于避免把任务期文档误当成长期真源文档，以及避免在模块文档未成形时直接进入代码实现。

文档分流：

- `docs/` 根目录用于业务主文档、总体架构文档与项目级长期说明。
- `docs/tasks/<task-id>/` 用于任务期文档，至少维护 `plan.md`、`execution.md`、`acceptance.md`。
- `docs/modules/<module-name>/` 用于模块长期真源文档，默认按 `contract/`、`design/`、`delivery/` 分层。
- `docs/tasks/` 不得替代 `docs/modules/`；任务目录中的长期有效内容，必须同步回写到对应模块文档。

实现前闸门：

- 只要某次实施会修改 `modules/<module-name>/`，就必须先确认存在对应 `docs/modules/<module-name>/`。
- 对新增模块或首次进入正式实现的模块，至少应先补齐：
  - `contract/`
  - `design/`
  - `delivery/code-map/`
  - `delivery/engineering/`
- 对长任务，若已经创建 `docs/tasks/<task-id>/`，则 `plan.md`、`execution.md` 与 `acceptance.md` 不能缺失。
- 长任务还必须有 `docs/ai/tasks/<task-id>/state.json`、`task.md`、`events.jsonl`；六份文件需同时存在并通过一致性校验。
- 若某项确实不适用，必须显式写明“不适用：原因...”，不得只写“不适用”或留空占位。

执行口径：

- 规则正文只定义边界和闸门，不在此重复实现脚本逻辑。
- 可执行校验统一收口到 WSL Python 校验器。
- Codex 正常链不依赖 hook；机械门禁由显式 WSL Python 校验器和测试承担。
