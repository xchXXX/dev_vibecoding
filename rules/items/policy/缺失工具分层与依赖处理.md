- 先区分机器公共工具、项目依赖、可选服务/GUI 能力，按当前用户选择的运行环境确定安装位置。不能把作者 WSL 工具集合当成跨平台核心依赖。
- 基础 harness install/doctor 只要求声明的 Python 基线。项目 Python/Node 依赖进入项目 manifest/lock 和同环境 venv/node_modules，不提升为全局包，也不跨系统复用。
- 系统工具缺失先说明当前操作实际需要的最小缺口、来源和目标；仅在已授权范围内安装，不静默提权或修改包来源。只读替代工具能取得等价证据时可以采用，并明确证据边界。
- Docker、数据库、浏览器自动化和云 CLI 按项目声明和本轮需要启用；未使用它们的任务不承担这些依赖。
- Browser、Computer Use 和 MCP 以宿主实际能力为准，不强开插件、不改 app-managed transport/缓存、不注册临时桥来绕过缺失。Windows 与 WSL 的能力分别核验。
- 广泛升级、卸载、发行版变更、新第三方源或破坏性修复先核实范围与授权；普通失败不自动扩大为这些动作。
