- 长任务正式实施前，必须先落盘方案文档，再落盘施工文档。
- 方案批准前必须冻结六要点：要做什么、不做什么、改哪些地方、怎么实现落地、怎么验收、有什么风险。
- 长任务六工件 `state.json / task.md / events.jsonl / plan.md / execution.md / acceptance.md` 全部必备，不能因为 `state.json` 是机器真源就删掉其他五份。
- 方案文档负责冻结目标、范围、约束、验收与阶段；施工文档负责冻结批次、顺序、验证、回退与审查返工路径。
- 在派发代码或配置实现前，必须由主协调器先完成当前批次核心文档与测试的同步更新，再进入实现。
- 若某批次确实不存在对应核心文档或测试，应在方案文档或施工文档中显式标记“不适用”，不得在执行时临时跳过。
- 对涉及多阶段、多子代理、多批次回收或需要维护 `state.json/task.md/events.jsonl` 的长任务，命中本规则后应转交 `skills/global-task-orchestrator/SKILL.md` 承担完整编排。
- 实施结束后不直接收口，进入 `review -> original implementer fix -> same reviewer re-review` 循环，直到可验收或按 finding 计轮后阻塞。
- 本规则只定义“何时进入长任务编排”与最小前置闸门，不在普通 rule 内复制 orchestrator skill 的完整控制面流程。
