- 先按当前操作判断缺失项属于机器公共工具、项目依赖隔离、可选能力还是 Windows 外部能力；不要用 Python 临时代替 `jq`、`rg` 等已知系统工具，也不要换平台绕过缺失项。
- 系统层机器公共工具安装到当前 WSL 发行版：例如 `git`、`jq`、`ripgrep`、Linux `nodejs`/`npm`。它们由 `config/ai/wsl-tool-baseline.json` 声明，不写入项目依赖文件，也不安装到 Windows 环境。默认先输出 plan；只有显式 apply、官方包、包名/来源/当前 WSL 发行版均明确且处于批准范围时才仅安装缺失包。`sudo` 不自动执行；对同一明确的最小安装，取得授权后无需再次授权。
- 项目 Python 依赖保留在 `pyproject.toml`、`requirements*.txt` 或 lock 文件，并安装到该项目的 Linux `venv`；项目 Node 依赖保留在 `package.json` 与 lock 文件，并安装到该项目的 Linux `node_modules`。不要把项目依赖提升为发行版包，也不要跨项目复用 Linux `venv` 或 `node_modules`。
- Playwright/Chromium、Docker、数据库、云 CLI 等是可选能力，必须由项目环境声明和当前任务需要共同决定。Windows 人工浏览不要求 WSL 浏览器；WSL 自动化不能混用 Windows 浏览器或缓存。
- Windows 原生 Agent 使用宿主实际提供的 Browser、截图与 Computer Use；Docker Desktop WSL Integration、账号/网络属于独立能力。当前 Windows 迁移不再使用 computer_use_wsl/browser_use_wsl，也不强制修改官方 node_repl/cua_repl transport 或插件缓存。项目 Linux 依赖继续在 WSL 管理；第三方服务按实际 MCP 所在平台配置路径。维护标志存在时旧外部能力声明属于待收口历史候选，不得据此重新注册桥或禁用原生插件。工具未暴露时报告阻塞，不能以临时强开开关、提权、改安全策略或猜测路径补救。
- 禁止广泛升级、卸载、发行版变更、新增第三方源、来源不明包、范围不清安装、自动重试和破坏性环境修复。需要这些动作时，先说明原因、影响和明确目标并取得授权。
