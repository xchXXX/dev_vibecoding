- 项目 Git、Python、Node、测试和构建在通用 WSL 开发发行版使用 Linux 原生工具，不以 Docker 专用发行版承担开发任务。Codex Agent 可运行在 Windows，通过明确的 `wsl.exe` 调用执行开发命令；原生文件工具、Browser、截图和 Windows 插件留在 Windows。
- 规则离线生成/校验、文档校验、bootstrap、sync、doctor、CFM 与测试在 WSL 使用 `python3` 和标准库；不通过 hook、临时 `.ps1` 或 `.cmd` 包装。`CODEX_HOME/.ai-harness/windows-native-transition.hold` 存在时暂停 bootstrap/sync 和旧 machine doctor 修复链，按该标志指向的任务收口后再解除；项目环境检查仍正常运行。
- 基础工具为 `git`、`rg`、`curl`、`wget`、`rsync`、`file`、`lsof`、`python3`、`python3-venv`、Codex 只读沙箱所需的 `bwrap`、Linux `node`/`npm`。
- 通用工具为 `jq`、`unzip`、`zip`、`tree`、`strace`、`shellcheck`、`shfmt`、`fzf`、`fd`、`sqlite3`、`dos2unix`、`build-essential`、`pkg-config`、`cmake`、`ninja`、`python3-pip` 和 Linux 原生 `pnpm`。
- 机器公共工具由 `config/ai/wsl-tool-baseline.json` 统一声明。`provision-wsl.py` 默认只输出计划，只有明确 apply 才能处理批准范围内的最小缺口；bootstrap 与 doctor 只检查，不静默安装或重复安装。`pnpm` 必须解析到 Linux 路径。
- 每个项目的 Python/Node 依赖、`TEMP` 边界和可选 capability 由项目环境声明和 `project-env-doctor.py` 在任务首次触及运行时时只读检查；机器 doctor 通过不代表项目依赖或 Windows 外部能力通过。
- 执行前确认 WSL 工作目录和依赖；普通非零退出进入失败闭环，不切换平台重跑，不增加 hook、通用 wrapper、command runner、逐命令 preflight、守护进程或自动重试。
- 不擅自重装依赖、搬仓库或创建副本。新进程实际的 `CODEX_HOME`、用户目录和规则加载位置必须核对，也不整目录复制 `.codex`。
