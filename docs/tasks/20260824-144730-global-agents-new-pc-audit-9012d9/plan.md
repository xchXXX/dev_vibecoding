# 全局 AGENTS 与新电脑迁移审计方案

## 任务目标

基于当前 `ai-harness`，为这台新电脑生成一份简洁、跨项目复用、可与项目级规则叠加的全局 `AGENTS.md`，并识别会影响 Codex 开发效率或正确性的迁移遗留问题。

## 背景与问题

仓库来自另一台电脑，活动态入口、生成的规则索引和部分文档仍含 `C:/Users/72385` 等旧绝对路径。Codex 官方约定全局指导位于 `CODEX_HOME/AGENTS.md`（默认 `~/.codex/AGENTS.md`），项目指导再从 Git 根向当前目录叠加，因此需要同时处理全局入口、项目入口和规则发现链路。

## 范围

- 审计 `AGENTS.md`、`rules/`、`scripts/`、`tests/`、核心 `docs/` 与当前 `~/.codex` 非敏感配置。
- 写入当前实际 Codex home 的全局 `AGENTS.md`。
- 修正少量直接影响当前运行的路径真源、测试合同和规则索引生成物。
- 运行 Codex sync/doctor、规则和任务文档验证。

## 非目标

- 不机械改写历史 run、复盘文档、旧任务状态和 benchmark 夹具。
- 不读取或修改 `auth.json` 内容，不输出 token、密钥或账号信息。
- 不接管第三方 skills、plugins、MCP 或整个 `~/.codex`。
- 不把项目级规则正文复制进全局 `AGENTS.md`。

## 约束与依赖

- Windows 脚本统一以 PowerShell 7 (`pwsh`) 执行。
- 全局路径优先跟随 `CODEX_HOME`，未设置时回退到 `%USERPROFILE%\.codex`。
- 仓库外写入仅限用户明确要求的全局 `AGENTS.md`，并保留已有内容或在冲突时停止。
- 规则索引是生成物，应通过生成脚本刷新，不手工伪造。

## 方案摘要

先并行完成路径、设计和本机环境只读审计；再冻结活动态修复清单；随后按“核心文档与测试合同 → 配置/入口实现 → 验证 → 独立审查”顺序实施。全局文件只写通用协作原则和 harness 发现方式，具体仓库规范继续由项目 `AGENTS.md` 与 `rules/registry/RULES_ENTRY.md` 提供。

## 风险与回退

- 若目标存在已有全局文件，先审计并最小合并；无法确定时停止覆盖。
- 若存在 `AGENTS.override.md`，报告遮蔽并在获得明确授权前不删除。
- 所有仓库内变更均可通过 Git diff 精确回退；全局文件写入前保留原内容快照或仅创建新文件。

## 验收标准

- 实际 Codex home 下的 `AGENTS.md` 非空、简洁且无旧用户硬编码。
- 活动态入口和当前规则索引不再依赖旧电脑路径。
- 相关文档、规则、sync 与 doctor 验证通过。
- 审计结论把问题分为“必须修复 / 建议修复 / 历史留痕保留”。

## 阶段划分

1. `planning`：只读审计与合同冻结。
2. `doc_sync`：同步核心入口文档、测试合同与迁移说明。
3. `test_sync`：先运行和必要时补齐当前批次验证。
4. `code_impl`：写入全局文件并刷新活动态生成物。
5. `review`：独立审查、复验与验收回填。

## 需先同步的核心文档与测试

- 核心文档：根 `AGENTS.md`、`rules/registry/RULES_ENTRY.md`、与当前路径发现直接相关的架构/安装说明。
- 测试：全局 AGENTS 路径合同、规则索引/校验、计划文档、Codex sync/doctor 最小链路。
- 历史留痕：不适用；只在最终审计中分类说明，不回写历史事实。
