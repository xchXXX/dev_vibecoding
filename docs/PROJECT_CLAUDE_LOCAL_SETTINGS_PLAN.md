## 当前状态冻结

### 1. 当前真实文件状态

- 当前对象：`C:\projects\pdf_ai\paddle_ocr\.claude\settings.local.json`
- 当前真实顶层结构只有 `permissions`
- 当前 `permissions` 下：
  - `allow` 为一长串历史白名单
  - `deny` 为空数组
  - `ask` 为空数组

### 2. 当前已知允许项风险概况

当前 `permissions.allow` 已知至少包含以下历史类别：
- 旧 SSH 入口
  - 包含旧服务器 `120.26.42.107`
  - 包含宽泛形式 `ssh root@120.26.42.107:*`
- 宽泛执行通配
  - 包含 `Bash(python:*)`
- 历史 git 提交命令
  - 包含旧 git commit heredoc 命令白名单
- 历史 Node 调试命令
  - 包含旧 `node require` 调试类命令

### 3. 当前问题分类

#### 配置语义冲突

- 官方语义已明确：`.claude/settings.local.json` 是“不进版本控制的个人项目配置”，用于 personal preferences / experimentation
- Claude Code 创建该文件时会配置 git ignore
- 当前该文件仍被 git 跟踪，且 `.gitignore` 未忽略它
- 因此当前仓库状态与官方语义存在直接冲突

#### 权限内容漂移

- 当前 `permissions.allow` 明显承载了大量历史遗留命令白名单
- 其中既有已失效的旧基础设施入口，也有过宽执行通配
- 该状态更像“历史便利项堆积”，而不是“最小个人项目本地偏好”

#### 作用域边界混淆

- 用户级 `~/.claude/settings.json` 已承载 hooks、插件等全局配置
- 当前项目 `.claude/settings.local.json` 不应继续承担全局共享配置职责
- 该文件也不应成为项目共享治理规则、runtime 托管或 merge/override 设计的承载点

### 4. 与其他 settings 层级的边界

- 设置优先级已知为：
  - `enterprise`
  - `CLI args`
  - `.claude/settings.local.json`
  - `.claude/settings.json`
  - `~/.claude/settings.json`
- 因此本文件的正式边界应收敛为：
  - 只承载个人在当前项目内的本地偏好或临时实验项
  - 不承担用户级全局配置的镜像、补丁或覆盖模板角色
  - 不承担项目共享 `.claude/settings.json` 的长期共享职责
  - 不扩展到用户级 settings merge/override 体系设计

## 目标状态冻结

### 1. 正式定位

项目 `.claude/settings.local.json` 的正式定位冻结为：
- 个人项目本地配置
- 默认不进版本控制
- 仅服务于当前操作者在当前项目中的本地偏好、临时实验或本地便利项
- 不作为团队共享规则文件

### 2. 顶层字段准入边界

#### 允许出现的顶层字段

- 仅允许承载与“个人项目本地配置”直接相关、且符合官方本地语义的字段
- 结合当前对象，子批次 C 首轮重点冻结在 `permissions` 这一顶层字段
- 如后续出现其他顶层字段，只有在能够证明其属于个人本地偏好/实验项时，才可进入同类治理

#### 不建议继续承载的内容

- 全局共享治理规则
- 需要跨用户共享的项目策略
- hooks/runtime/receipt 相关配置
- 插件托管或运行时目录治理
- 对用户级 `~/.claude/settings.json` 的镜像性重复

#### 明确不应在该文件继续出现的内容

- 过宽的执行通配白名单
- 已失效的旧服务器入口
- 面向历史一次性操作沉淀下来的白名单
- 任何试图把该文件当成团队共享准入清单的内容

### 3. 当前对象分类冻结

#### 必须保留为个人项目本地配置

- 当前未识别到必须保留的现存项
- 也即：在已知真实内容中，当前没有任何一项被判定为“必须继续保留在仓库中的现存本地配置”

#### 可选本地便利项

- 仅限操作者个人在当前项目中短期确有需要、且作用域明确、风险可控的最小命令授权
- 该类对象可以继续存在于个人本地 `.claude/settings.local.json`
- 但应满足：
  - 本地自管
  - 默认不进版本控制
  - 不依赖宽泛通配
  - 能明确对应当前仍在使用的真实工作流

#### 历史遗留待清退项

- 旧 git commit heredoc 命令
  - 属于历史操作便利项
  - 不应继续作为项目共享历史白名单保留
- 旧 `node require` 调试命令
  - 属于历史调试便利项
  - 缺乏当前项目层长期保留的必要性
- 任何已无法对应当前实际工作流的旧命令白名单

#### 明确不应在该文件继续出现的项

- 旧 SSH 入口
  - 包含旧服务器 `120.26.42.107`
  - 属于已过时的基础设施入口，不应继续保留
- 宽泛 SSH 通配
  - 如 `ssh root@120.26.42.107:*`
  - 风险高，且明显超出最小本地便利项边界
- 任意 Python 执行通配
  - 如 `Bash(python:*)`
  - 风险高，不应继续作为默认本地授权口径
- 其他无法限定作用域的宽泛命令白名单

### 4. 当前 `permissions.allow` 大类归档与风险分级

| 类别 | 当前归类 | 风险级别 | 冻结口径 |
|---|---|---|---|
| 旧 SSH 入口 | 明确不应继续出现 | 高 | 视为历史基础设施遗留，后续实施时应从项目仓库口径中清退 |
| 宽泛 SSH 通配 | 明确不应继续出现 | 高 | 不符合最小本地便利项原则，不应继续保留 |
| 任意 Python 执行通配 | 明确不应继续出现 | 高 | 权限范围过宽，不应继续保留 |
| 旧 git 提交 heredoc 命令 | 历史遗留待清退项 | 中 | 不再作为共享白名单保留，后续迁回个人自管或直接废止 |
| 旧 `node require` 调试命令 | 历史遗留待清退项 | 中 | 不再作为共享白名单保留，后续迁回个人自管或直接废止 |
| 仍可证明必要且范围最小的个人便利项 | 可选本地便利项 | 低到中 | 仅允许留在个人本地且不进版本控制 |
