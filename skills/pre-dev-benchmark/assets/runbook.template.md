# {{TITLE}} Runbook

## 1. 准备阶段

- 确认 fixture 路径和清理规则。
- 确认哪些 suites 属于诊断，哪些属于验收。
- 确认证据要保存到哪里。

## 2. 执行顺序

1. 先跑诊断 suites。
2. 先修复明显的 harness 或 fixture 问题，再相信验收结果。
3. 只有在诊断输出可解释之后，才运行验收 suites。

## 3. 证据留存

- 保存唯一 PASS 标记、日志、报告和生成物。
- 保存足够定位失败层级的失败证据。
- 记录失败来自产品行为本身，还是来自 benchmark harness。

## 4. 判定规则

- 是否通过验收，只由标记为最终闸门的 suites 决定。
- 诊断回归只有在它使验收结果失效，或暴露出真实产品缺陷时，才应阻断。

## 5. 迭代说明

- 只有在产品范围变化时才更新 fixtures，而不是因为当前实现不好测就临时改题。
- 尽量保留 case id，使不同迭代之间的 benchmark 结果可比较。
