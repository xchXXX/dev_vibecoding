## 背景与问题

- `src/report.js` 直接依赖 `calculateInvoice`，报表层既承担渲染也隐含绑定了价格计算流程。
- `src/pricing.js` 只有基础函数堆叠，缺少输入归一化、统一折扣配置和可复用的明细结构。
- 测试只覆盖少量 happy path，对空购物车、未知会员等级、金额舍入等边界缺少约束。
- README 仅说明评测背景，没有说明模块职责、公开接口和验证方式。

- 需先完成文档与测试落盘，再进入代码实现。

## 方案摘要

- 将价格计算重构为“归一化输入 -> 小计计算 -> 折扣计算 -> 税费与总额汇总”的清晰管线。
- 用常量表表达会员折扣规则，减少条件分支散落。
- 在报表模块中抽出行拼装逻辑，显式依赖发票对象或计算函数，降低展示层对计算细节的侵入。
- 增补覆盖空输入、未知会员、金额舍入和报表逐行输出的测试。
- 更新 README 和模块文档，说明接口、行为与验证命令。

## 风险与回退

- 风险：重构时若改动金额舍入顺序，可能导致总额与旧行为不一致。
- 风险：新增输入归一化可能改变异常输入的容忍度。
- 回退：保留原有公开函数名与参数顺序；若测试发现行为漂移，可优先回退到旧的金额计算顺序，同时保留文档和测试补充。

- `node tests/run-tests.js` 通过。
- 报表渲染模块不再直接混杂金额推导逻辑，职责边界比当前实现更清晰。
- README 与模块文档可说明模块用途、接口、验证方法和已覆盖场景。
- 测试覆盖至少包括原有 happy path、空购物车、未知会员折扣、金额舍入与报表输出结构。
