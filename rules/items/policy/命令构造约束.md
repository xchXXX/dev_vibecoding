- 项目开发链使用 WSL Linux 原生命令；Windows 原生 Agent 通过 `wsl.exe -d <已核实发行版> --cd <Linux项目路径> -- bash -lc '<命令>'` 进入同一项目，WSL Agent 直接执行。Windows 原生文件/Browser/插件操作使用 Windows 入口，不能把 Linux 路径直接交给 Windows 工具。执行前确认解释器、脚本路径、参数路径和工作目录；不用 hook 或临时 `.ps1`/`.cmd` 包装项目命令。
- 带空格或中文的路径作为单独且正确引用的参数传递；目标程序退出码必须原样判断，不由后续成功命令覆盖。
- 不新增通用路由 wrapper、逐命令 preflight、守护进程或自动重试；复杂逻辑优先放入已有正式 Python 脚本，或拆成可审阅的分步命令。
- 正则、JSON、长文本与路径参数不得混在脆弱多层 shell 字符串中；优先使用 Python argv、JSON 文件接口或明确的 heredoc 输入。
- 将多个候选路径传给 `rg`、测试或构建前，先过滤不存在的可选目录；必需目录缺失则报告真实阻塞。
- 一次性排障脚本只能放在规则允许的临时落点并在完成后清理；可复用脚本必须进入正式真源目录并由文档和测试覆盖。
- `ghost snapshot`、`NUL` 等外层异常先按平台噪音候选判断；只有目标命令失败或目标产物受损才升级为真实命令失败。
- 若失败来自复杂 one-liner、自拼 quoting 或多层 shell 解析，优先简化命令结构，再按命令失败闭环查询和重试。
