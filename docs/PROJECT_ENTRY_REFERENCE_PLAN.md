# PROJECT_ENTRY_REFERENCE_PLAN

## 背景与目标

本文是 `Phase 7 / 子批次 B：项目入口与全局引用收口方案` 的正式方案文档。

目标：
- 冻结项目入口文件的收口策略
- 明确哪些入口继续保留项目增量职责
- 明确哪些入口后续改成引用全局真源
- 明确哪些入口后续只保留索引/跳转职责
- 明确哪些入口继续延后处理，不在当前批次直接收口

本批只定方案，不直接修改项目入口文件。

## 目标状态定义

- `保留项目增量正文`
  - 入口继续保留在项目层
  - 仅承载本仓增量规则、项目边界和项目专属说明
- `改成引用全局真源`
  - 入口继续存在，但正文后续尽量缩减为对 `ai-harness` 真源的引用
  - 仅在必要处保留项目差异说明
- `改成索引/跳转入口`
  - 入口继续保留，但主要职责是导航、跳转、列出本仓入口
  - 不再重复维护通用正文
- `延后处理`
  - 当前不进入直接收口
  - 后续单独结合运行时、project local config 或历史遗留方案处理

## 与子批次 A 分类体系的映射

- 子批次 B 的 `保留项目增量正文` 对应子批次 A 的 `保留`
  - 两者都表示对象继续留在项目层，并承载本仓仍需长期维护的增量规则或项目专属说明
- 子批次 B 的 `改成引用全局真源` 对应子批次 A 的 `替换为全局引用`
  - 两者都表示项目层正文后续收缩为对 `ai-harness` 真源的引用，仅保留必要项目差异
- 子批次 B 的 `改成索引/跳转入口` 仍归属于子批次 A 的 `替换为全局引用`
  - 这是入口类文件在实施层的更窄落点，不是新增分类
  - `docs/ai/README.md` 后续承担导航、跳转和本仓入口索引，本质仍是由全局真源承载通用正文，因此不构成 A 口径漂移
- 子批次 B 的 `延后处理` 对应子批次 A 的 `延后处理`
  - 当前只记账，不在入口收口批次直接改写
- 子批次 A 的 `本地化` 不作为子批次 B 的目标状态
  - 该类对象由子批次 C 单独承接
- 子批次 A 的 `移出共享真源` 也不作为子批次 B 的目标状态
  - 当前这批入口对象里未发现应立即归入该类的对象
  - 若后续子批次 B/C/D/E 发现项目专属对象被误判为可全局化候选，应回退到 `移出共享真源` 分类重新处理

## 与子批次 A 资产盘点范围的衔接

- 子批次 A 的强制盘点清单未把 `AGENTS.md` 列为必须逐对象展开的资产
- 但 `PROJECT_ADAPTER_CLEANUP_PLAN.md` 已把 `AGENTS.md` 纳入项目层入口治理范围，因此子批次 B 将其纳入“项目入口收口对象”属于承接总方案，不是跳出子批次 A 范围
- 子批次 B 只补充入口治理策略，不改写子批次 A 已冻结的五类正式分类

## 各类入口的验收口径

### `保留项目增量正文`
- 文档或入口继续存在
- 明确只保留项目增量，不再复制全局通用全文
- 引用全局真源的入口位置清晰

### `改成引用全局真源`
- 文档继续存在
- 通用正文显著收缩
- 清晰指向 `ai-harness` 对应真源
- 如需保留内容，仅保留本仓差异说明

### `改成索引/跳转入口`
- 文件继续存在
- 核心职责变成导航、索引、跳转
- 不再承担长篇规则正文

### `延后处理`
- 本批只记账，不实施
- 必须明确后续依赖的治理批次
- 不因当前收口方案直接触发删除或运行时清理
