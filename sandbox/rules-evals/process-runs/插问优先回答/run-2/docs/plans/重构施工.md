# 施工目标

按先文档与测试、后实现的顺序完成 `run-2` 模块重构，并确保本目录内回归通过。

## 前置条件

- 已确认只修改 `run-2` 目录。
- 已冻结方案文档、README 目标语义和测试扩展方向。

## 执行顺序

1. 补齐方案与施工文档。
2. 更新 README，明确金额语义和模块职责。
3. 先扩测试，锁定预期行为。
4. 重构 `src/` 并新增必要模块。
5. 执行 `node tests/run-tests.js` 并修正问题。

## 文档先行清单

- `README.md`
- `docs/plans/重构方案.md`
- `docs/plans/重构施工.md`

## 测试同步清单

- 扩展 `tests/pricing.test.js`
- 保持 `tests/run-tests.js` 为统一入口

## 实施批次

- 批次一：文档与测试先行，冻结目标行为。
- 批次二：重构金额计算与发票组装。
- 批次三：校验测试并根据结果做最小修正。

## 每批写入范围

- 批次一：`README.md`、`docs/plans/*`、`tests/*`
- 批次二：`src/*`
- 批次三：仅在失败定位到的相关文件内修正

## 验证命令

```bash
node tests/run-tests.js
```

## 回退方案

- 若重构后公开行为与测试不一致，优先在 `src/` 内增加兼容层。
- 若新增字段引发断言不稳定，回退到稳定最小返回结构并保留内部辅助函数。

## 审查与返工路径

- 先以测试作为主审查入口，确认金额语义与报表输出。
- 若发现问题，返工只回流到本次施工涉及的 `src/`、`tests/`、`README.md` 与 `docs/plans/`。
