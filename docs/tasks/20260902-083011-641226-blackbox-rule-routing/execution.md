## 施工目标

用五个完全隔离的新子代理执行普通任务，再用第二轮追问收集实际读取文件，并由独立 reviewer 评估行为。

## 前置条件

- 用户已确认六要点任务合同。
- 写入前已冻结范围、验收和风险。

## 执行顺序

分批并行启动 fork_turns=none 子代理；首轮普通任务，第二轮只追问上一轮读取文件；独立 reviewer 对照任务、输出、读取清单和产物给出结论。

## 测试同步清单

4. 五组证据收齐后，启动不继承本对话的独立 reviewer 做统一判定。

## 证据边界

第二轮清单是代理自报，不是底层工具访问日志。它可以用于行为抽查，但不能证明清单绝对完整，也不能把“未自报某文件”直接当作“底层一定没打开”。

## 回退方案

- 子代理自报读取清单不等于底层工具审计日志，最终报告必须明确证据边界
- README 改字代理会写临时夹具，必须限制到精确路径并清理
- 并发槽位有限，需要分两批派发

## 审查与返工路径

本任务只执行行为测试，不修改运行逻辑。reviewer 未给出 `fail`，因此没有进入修复循环；两处过读作为后续改进候选保留，若用户要求根治应另立实施任务。
