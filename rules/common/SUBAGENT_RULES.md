# Common Subagent Rules

- 每个 batch 或 phase 都必须委派子代理。
- `Plan Window` 只能派阅读型子代理；执行型子代理只能由 `Execute Window` 派发。
- `Plan Window` 进入 `plan freeze` 后不得继续委派子代理。
- `Plan Window` 冻结方案时必须同步写出正式 `plan.md` 与 `plan.json`；其中 `plan.md` 是语义真源，`plan.json` 是结构化投影。
- 只要任务进入 orchestrator 流程，无论任务大小，都必须先在 `Plan Window` 与用户交互并冻结方案，不得跳过规划直接实施。
- `Execute Window` 必须先完整阅读冻结 `plan`，再派阅读型子代理补局部上下文。
- 主协调器与子代理补方案上下文时，默认优先读取 Markdown 真源，再按需读取 JSON 合同；不允许只凭 JSON 代替方案理解。
- `Execute Window` 派出阅读型子代理后，只允许做非重叠的协调准备，不得并行重复阅读同一批上下文。
- `Execute Window` 不得自行改写冻结 `plan` 语义；若 `plan.md` 与 `plan.json` 冲突，必须停止并退回主窗口处理。
- 文档、清单、测试、配置与代码有依赖时必须串行；正式实施顺序固定为“冻结方案 -> 文档/清单 -> 测试 -> 代码/配置”，不得跳步。
- 若某一分支确实不存在，必须在冻结方案中显式标记为不适用，不能在执行阶段临时省略。
- 主协调器必须在线等待子代理自然完成，不得提前收口或跳步。
- 当前批次全部子代理完成并验收前，不得进入下一步。
- 阅读型子代理必须给出相关代码路径、相关文档路径与证据摘要。
- `work_order` 必须包含最小可执行改法：`change_spec`、`execution_steps`、`verification_steps`、`dispatch_message_raw`。
- 执行型工单必须显式给出 `read_paths_mandatory` 与 `evidence_summary`。
- 复杂任务必须补 `dispatch_packet`，并在 `work_order` 中写明 `dispatch_packet_path`。
- 执行型工单必须以 `return_packet` 作为完成闸门，未写回执不得视为完成。
- `return_packet` 正文必须由执行该工单的子代理填写；主协调器不得代写正文，缺失或不合格时必须退回原执行子代理补写。
- 执行型子代理必须先读取 `read_paths_mandatory`，不能只靠摘要实施。
- 主窗口默认只接收结构化结果与必要摘要，不接收长过程全文。
- 对任何落盘文件，能用中文表达的地方尽量使用中文；字段名、路径、脚本参数与代码标识符保持机器可读。
- 主协调器派发子代理时必须显式要求中文输出；除机器可读字段外，大面积英文输出默认不合格，应退回改写。
- 统一落盘口径在全局 `docs/SUBAGENT_GOVERNANCE.md` 中定义，项目仓库只保留引用与增量规则。
- 阻断问题一律退回原执行子代理返工，主协调器不直接代修。
- 审查按风险触发；复验阶段才默认需要专门审查子代理。
- 审查子代理如要求补测试，必须输出可直接落地的具体测试用例。
- 代码子代理每轮都必须补齐并跑通本轮要求的测试。
- 测试断言必须面向行为与契约，避免对内部实现过拟合。
- 测试通过不能替代代码审查通过。
