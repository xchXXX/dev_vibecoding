# 消费项目适配

项目只维护自己的边界、增量规则、业务代码和证据。普通使用不要求先改造目录结构或创建 GTO 状态，已有框架目录可按项目规则声明。共享规则和方法从当前安装发现，不复制成项目私有第二真源。

## 最小入口

在项目 `AGENTS.md` 写清语言、代码/文档入口、当前环境、运行和验证方式，以及本项目额外约束。全局协作来自已安装 AGENTS 管理区块；若项目已有 `rules/registry/RULES_INDEX.json`，读取其元数据及固定三条规则，其余按当前语义选择。

未建立项目规则索引时，可直接使用全局安装索引。若要离线合并全局规则，显式指定已经核实的安装规则根给 `--global-rules-root`，只导入 `scope != project`；不要扫描其他 clone 或复制作者绝对路径。生成与校验脚本的真实参数以 `--help` 为准。

## 按需目录

- 模块代码及长期文档按项目规则维护，新增落点参考全局通用存储规则。
- 长任务如需持续说明，用 `docs/tasks/<task-id>/` 保存相称计划、执行和验收证据；普通任务不强制六工件和固定章节。
- 仅显式选择 GTO 后按该技能创建 `docs/ai/tasks/<task-id>/` 的机器状态，并维护六工件及 preflight。
- 冻结夹具放 `tests/fixtures/`；本次执行临时内容和证据分别在 `.tmp/`、`.artifacts/`，不把执行产物放入夹具目录。
- 项目环境与 Git 策略放 `config/ai/`；本地秘密使用忽略的 `config/local/` 或环境变量，不能进入共享包。

项目配置不能覆盖全局 `codex_home`、`skills_dir` 或安装所有权。Python 虚拟环境及 Node 依赖由项目环境选择决定，Windows 与 Linux/WSL 不混用。

## 方法与编排

benchmark 输出目标、fixture、成功条件和证据位置；fix 输出最小复现及命中证明；CFM 只处理真实失败链。三种方法均可在没有 GTO 时使用，证据写入已有任务说明或本次回复，既有有效证据可复用。

用户明确选择 GTO 后，从实际加载的 `global-task-orchestrator` 技能读取方案、流程、schema 与运行证据合同。自定义 `skills_dir` 时不能假定技能位于规则根或源码仓库。缺少该模块或真实代理能力时报告 GTO 阻塞，普通规则与方法继续按授权工作。

## 接入核验

确认当前项目入口、环境和验证命令正确；确认全局安装与项目覆盖的边界；新会话验证规则及方法确实可见。没有 GTO 的项目应能完成普通配置测试或修复验证示例，并且没有自动生成 task_id、state.json 或编排 preflight。安装步骤见 [INSTALL](INSTALL.md)。
