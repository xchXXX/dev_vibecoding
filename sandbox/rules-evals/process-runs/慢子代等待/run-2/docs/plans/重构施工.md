# 重构施工

## 施工目标

按已冻结方案完成模块分层重构、文档补全和测试扩展，并保持目录外零改动。

## 前置条件

已确认目标目录现状与现有公开接口。
已确认验证命令为 `node tests/run-tests.js`。
已确认本次允许新增目标目录内文件。

## 执行顺序

1. 先落盘方案文档与施工文档。
2. 更新 README，补模块职责与验证说明。
3. 先扩展测试，锁定预期行为和边界。
4. 再重构 `src/` 的职责拆分与导出。
5. 运行验证命令并根据失败结果修正。

## 文档先行清单

- `docs/plans/重构方案.md`
- `docs/plans/重构施工.md`
- `README.md`

## 测试同步清单

- 扩展 `tests/pricing.test.js`，覆盖金额工具、发票计算与报表输出。
- 保持 `tests/run-tests.js` 作为单一执行入口。

## 实施批次

第一批：文档冻结与测试扩展。
第二批：源代码分层重构与接口兼容。
第三批：执行验证并做最小修正。

## 每批写入范围

第一批仅写入 `docs/plans/`、`README.md`、`tests/`。
第二批仅写入 `src/`。
第三批按测试结果在 `src/` 或 `tests/` 内做最小补丁。

## 验证命令

`node tests/run-tests.js`

## 回退方案

若重构行为偏移且短时间无法收敛，优先回退新增分层中的局部实现，保留测试与文档，再恢复与原始金额语义一致的计算路径。

## 审查与返工路径

先基于测试结果自审金额语义、接口兼容性和文档一致性。
若出现 findings，返工直接回到本次施工上下文处理，再重新执行同一验证命令收口。
