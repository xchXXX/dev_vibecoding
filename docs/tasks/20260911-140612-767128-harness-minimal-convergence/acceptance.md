## 黑盒失败报告与停止规则

本节的停止条件是：**准备就绪后的正式第一轮黑盒验收，没有达到冻结的预期效果**。投放、版本、环境、输入污染等准备检查问题按上方 A2 自主修复复查，不适用“黑盒效果失败就等用户”的规则。

首轮有效观察出现效果问题时，保留原始输入、版本、轨迹和产物，不自动补提示、改 skill/产品后重跑或开始第二轮。可完成本轮其余独立且仍有意义的预定检查，集中报告；有依赖的剩余项如实标记未执行，不能假造完整覆盖。被测业务内部按 GTO 正常处理问题属于观察内容；外层已经确认的 skill 效果缺陷，不能借内部循环或准备复查来偷偷纠正并改判。

A 根据现有证据定位原因，区分确认根因与待验证假设。主协调器直接向用户报告：

1. 首轮场景、真实会话 ID、加载候选、预期效果及实际偏差。
2. 输入、轨迹、产物或错误证据，以及通过、失败、未触发和未执行的范围。
3. 已证实根因和仍待验证假设，影响的 REQ/AC。
4. 修复方案、修改位置、需同步的测试文档、投放和建议补测范围。
5. 保留的有效结果，以及等待用户决定的后续工作。

报告前允许只读归因，不以诊断名义修改产品或重新跑完整效果测试。用户明确决定后才安排修复和第二轮；原始整体授权或剩余预算不代替这个决定。普通 Review/验收与开测前准备仍可依授权自行闭环，不能把其通过当作正式黑盒已通过。
