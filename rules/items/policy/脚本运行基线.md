- Codex 正常链固定运行在通用 WSL 开发发行版中；日常文件操作、Git、Python、Node、测试和构建使用 Linux 原生工具，不以 Docker 专用发行版承担开发任务。
- 规则离线生成/校验、文档校验、GTO、bootstrap、sync、doctor、CFM 与测试统一使用 `python3` 和标准库；正式入口与验收链不调用 hook、`.ps1` 或 `.cmd`。
- 基础工具为 `git`、`rg`、`curl`、`wget`、`rsync`、`file`、`lsof`、`python3`、`python3-venv`、Linux `node`/`npm`。
- 通用工具为 `jq`、`unzip`、`zip`、`tree`、`strace`、`shellcheck`、`shfmt`、`fzf`、`fd`、`sqlite3`、`dos2unix`、`build-essential`、`pkg-config`、`cmake`、`ninja`、`python3-pip` 和 Linux 原生 `pnpm`。
- 工具部署批次负责一次性安装；bootstrap 与 doctor 只检查，不静默安装或重复安装。`pnpm` 必须解析到 Linux 路径。
- 执行前确认 WSL 工作目录和依赖；普通非零退出进入失败闭环，不切换平台重跑，不增加通用 wrapper、command runner、逐命令 preflight、守护进程或自动重试。
- 不擅自重装依赖、搬仓库或创建副本。新进程实际的 `CODEX_HOME`、用户目录和规则加载位置必须核对，也不整目录复制 `.codex`。
