- 普通委派的语义判断由 Codex 完成；Codex 读取 `task.md` 的“做什么、不做什么、会改哪里、怎么实施、怎么验收、有哪些风险”六要点，并在平台真实派遣 prompt 中显式给出 `assignment`、`read_paths`、`write_paths` 与验收要求。平台必须用真实无历史参数启动子代理，并由控制器将返回的真实 `platform_agent_id` 与 `context_mode=isolated` 机械记录到 `state.json` 和 `events.jsonl`。
- 提示词中的“不要读取历史”只是一项行为约束，不是上下文隔离证明；平台不支持无历史派发时必须阻塞，不得伪报隔离成功。
- 子代理不得自行读取完整 state，普通委派只消费平台真实派遣 prompt 中显式给出的 `assignment`、`read_paths`、`write_paths` 与验收要求。
- 控制器只机械维护 `state.json`、`events.jsonl`；仅 `build-review-brief` 会生成复审 brief。
- finding 使用稳定唯一 ID。revision 3 保存发现者复现、根因、修复方案、真实失败证明及文档同步结论，区分原 reviewer 与原验收者的复核职责；routed_to 固定为原整合责任者，原并行实现者不参与返工。旧任务保持原实现者返修路由，局部复审均回原 reviewer。
- 原 reviewer 的 re-review 输入为目标 finding、fix delta、最新候选和必要证据；复审可补新 finding。若 changed paths 或语义影响扩大，必须说明原因并扩大覆盖，保留旧 finding ID 和历史。
- 同一 finding 最多三轮返修；达到上限仍未关闭时，转为 `blocked` 或人工裁决。
- revision 3 由独立测试子代理先写初始测试，实现 TDD 全部完成后交唯一整合子代理，再做一次完整独立审查及必要范围复审；首次真实验收逐点登记，可按独立范围分开完成；全部必需点当前有效通过后完成，不要求单轮全量。验收 finding 由原整合责任者修复并重新整合后，直接交同一验收者范围复验及修复 delta 检查，不退回 reviewer；保留验收前完整审查及复审证据。通过后由一个文档子代理排查并直接同步正式文档遗漏和六工件事实，不增加双人文档 review；实质行为或契约变化返回验收链。旧 revision 2 保持原有 final/pass 门禁。 reviewer 真实身份与被审实现者、修复者和整合者独立。
