# 普通任务的黑盒评估

本页是 pre-dev-benchmark 自包含的方法参考，适用于未启用 GTO 的 Skill、CLI、API、UI 与工作流评估。不定义编排阶段、六工件、task_id 或 GTO 批准协议。用户显式选择 GTO 后，其状态门禁与成本批准另以对应技能合同为准。

## 先确定证据，再选入口

对每项目标冻结候选版本、输入与夹具、触发动作、可观察证据、禁止行为、预算和停止点。优先选择能直接证明目标的最低成本入口：准备检查、首次响应、单次门禁/副作用、合法中间状态恢复，最后才考虑必须跨阶段的完整链。准备成功不代表效果通过；机械测试不能替代真实会话选择、真实代理身份或 UI 行为。

可复用同候选仍有效的证据，说明未失效理由。需要外部写入、额外资源或超出已授权范围的运行时，先完成具体场景准备再核实权限；方法本身不新增重复批准或扩大授权。

## 评估技能

被测输入只给正常业务需求，不泄露技能名称、预期动作或隐藏答案。评分材料与业务输入分开；需要无历史会话时由平台真实隔离参数及会话身份证明，不能仅靠“请忽略历史”或执行者自报。先记录基线的实际行为，再用同一场景比较候选，保留原始失败。

从实际安装位置核实 skill、references、脚本及候选哈希。新会话是否加载另留证；磁盘安装、已有会话 reread 或帮助命令成功均不能独立证明自动选择正确。

## 执行与停止

在隔离临时目录使用冻结夹具副本，不改真源夹具。运行前确认观察手段、预算和自有资源清理范围。达到目标证据、出现禁止行为、超出预算或观察不可继续时停止；不能为了“跑绿”不受限重试。返工需要明确修改和重新验证范围，不改写首轮事实。

结果使用以下含义，写入已有报告或任务说明即可：

| 结果 | 判定 |
| --- | --- |
| PASS | 准备有效，最小目标证据齐全且无禁止行为 |
| EFFECT_FAIL | 准备有效、触发成立，行为违反目标 |
| PREPARATION_INVALID | 有证据证明版本、输入、环境、夹具或观察前提不成立 |
| NOT_OBSERVED | 合同允许本轮不出现目标分支；不算覆盖通过 |
| INCONCLUSIVE | 证据不足、冲突、中断或预算耗尽，不能作通过判断 |

准备问题修正后保留原成本和记录；不能把有效条件下的效果失败改称准备无效。报告候选、实际入口、输出/退出码、身份、证据位置、结果、停止原因、成本、清理和未覆盖项。

## 记忆访问

需要评价干净接收者时，分别记录 MEMORY 注册表、历史摘要、其他长期记忆与 CFM 的公开可观察访问；缺少完整轨迹则记 unknown，不从提示词或自报推断未读。CFM 仅处理真实非预期失败链；按预先声明的最小 TDD Red 例外执行，不为了业务答案查询失败经验。
