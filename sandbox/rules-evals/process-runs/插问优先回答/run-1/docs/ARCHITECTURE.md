# 模块架构

## 重构目标

当前模块原先把“金额计算”和“报表字符串生成”直接串在一起，测试也把两者混在一个文件中，导致：

- 金额规则变更时，报表测试定位不清。
- 报表格式调整时，容易误伤金额逻辑。
- 复用金额工具时只能间接依赖 `report.js`。

本次重构把职责拆成三层：

1. `money.js`
   - 提供金额四舍五入与格式化。
   - 不感知会员等级、税率或报表文案。
2. `invoice-calculator.js`
   - 负责 subtotal、折扣规则、税额与总额计算。
   - 输出纯数据对象，供测试或上层消费。
3. `report.js`
   - 负责把输入参数转换为报表视图模型，并渲染成文本。
   - 允许单测直接验证“模型组装”和“字符串渲染”。

## 边界

- `invoice-calculator.js` 不输出任何报表文案。
- `report.js` 不内嵌折扣公式或税额公式，只消费 calculator 的结果。
- 所有金额展示统一经 `money.js` 格式化，避免不同文件重复 `toFixed(2)` 细节。

## 验收关注点

- 原有折扣与税额结果保持不变。
- `tax` 继续按折扣后金额计算。
- 报表输出格式兼容既有调用方。
- 测试分层后，金额逻辑与报表逻辑可分别回归。
