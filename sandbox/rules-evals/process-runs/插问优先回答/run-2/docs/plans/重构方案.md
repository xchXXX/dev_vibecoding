# 任务目标

在 `run-2` 目录内完成一次完整重构，解耦定价与报表逻辑，补齐文档与测试，并确保 `node tests/run-tests.js` 通过。

## 背景与问题

当前实现把“金额规则定义”“发票汇总”和“文本报表输出”压在很少的几个函数里，职责边界不够清晰。测试只覆盖少量 happy path，难以在重构时保护语义。

## 范围

- 只修改当前目录内的 `src/`、`tests/`、`README.md` 与 `docs/plans/`。
- 增加必要的内部模块文件，但不改动目录外任何文件。

## 非目标

- 不引入外部依赖。
- 不改造测试运行方式。
- 不扩展到 Web、CLI 或持久化能力。

## 约束与依赖

- 必须保证 `node tests/run-tests.js` 可通过。
- 说明性内容使用中文，代码标识符保持原样。
- 只允许修改当前目录。

## 方案摘要

将实现拆成四层：

1. `money` 层统一金额舍入和展示。
2. `pricing` 层只负责价格、折扣和税额计算。
3. `invoice` 层负责产出稳定的发票摘要对象。
4. `report` 层只消费发票摘要并输出字符串。

同时扩充测试，覆盖折扣基于 `subtotal`、未知会员等级、空购物车、税额舍入和报表输出。

## 风险与回退

- 风险：重构后字段命名变化可能影响测试或上层调用。
- 回退：若新结构导致行为偏差，可在本目录内保留兼容导出或回退到上一版字段形状。

## 验收标准

- `src/` 内职责边界清晰，报表渲染不再直接承担定价规则。
- README 明确定义 `subtotal` 与会员折扣关系。
- 测试覆盖核心金额语义与边界场景。
- `node tests/run-tests.js` 返回成功。

## 阶段划分

1. 冻结方案与施工文档。
2. 更新 README 与测试，定义目标行为。
3. 重构实现并对齐测试。
4. 运行验证并收口。
